# Scoreboard for Android

Kotlin/Compose over the **same Rust core the iOS app ships**
(`crates/app-core`, via uniffi). The parity contract lives in the repo root's
`CLAUDE.md`: strings, logic, and behavior are shared — through the core and
the server's descriptors — while layout, navigation, and platform plumbing
are deliberately Android-idiom.

## Status

Proven working:
- **The Kotlin bindings run against the real core.** The generated bindings
  (`core/src/main/kotlin/uniffi/app_core/app_core.kt`) were compiled and
  executed on the JVM over JNA against the host build of `libapp_core` —
  shared rules (league grouping, labels, guide copy) return byte-identical
  results to Swift.

Written, pending first on-device build (this machine has no Android SDK):
- `core/` — the bindings as an Android library over per-ABI `libapp_core.so`.
- `app/` — pairing screen (code entry), board screen: online dot, brightness
  (knob detents), mode picker with follow-the-glass selection, now-showing
  games rendered from the server's pushed RGBA frames (variable height,
  nearest-neighbor).

Not started (each its own milestone):
- **BLE provisioning** ("Add Scoreboard" from scratch) — the GATT contract is
  in `firmware-rs/src/ble.rs`; until it lands, pair with the code an
  already-provisioned board shows.
- Settings surfaces (leagues, spoilers, screen/timers, updates), multi-board,
  the LED-look share export.

## Building

One-time setup:

```bash
# Android Studio (or commandline-tools) with SDK 35 and NDK r27+
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=~/Library/Android/sdk/ndk/<version>
```

Then:

```bash
./build-core.sh        # libapp_core.so per ABI + fresh Kotlin bindings
./gradlew assembleDebug
```

`build-core.sh` is the only correct way to refresh the core — the same rule
as `ios/build-core.sh`.

## Identity

The Ed25519 controller seed is generated by the core on first launch and kept
in `EncryptedSharedPreferences` (the Keychain sibling). **An Android install
is a new controller**: the server allow-lists controller pubkeys per board,
so this app pairs itself with the code on the panel — it does not inherit an
iPhone's grant.
