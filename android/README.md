# Scoreboard for Android

Kotlin/Compose over the **same Rust core the iOS app ships**
(`crates/app-core`, via uniffi). The parity contract lives in the repo root's
`CLAUDE.md`: strings, logic, and behavior are shared — through the core and
the server's descriptors — while layout, navigation, and platform plumbing
are deliberately Android-idiom.

## Status

Feature-complete against the iOS app for everything a phone does:

- **Set up a new scoreboard over Bluetooth** — scans by name, reads the
  network list the BOARD scanned, writes credentials (and optionally a server
  + TLS pin) in the order the firmware requires.
- **Pair** an already-provisioned board with the code on its panel.
- **Dashboard** — live/upcoming cards from the server's pushed frames, ring
  states, add/remove/pin/hide/share per card, brightness, the mode picker,
  quiet-hours note, reset rotation, league cards, board switcher.
- **All games** — grouped, searchable, add/remove.
- **Leagues** — subscriptions, teams, rounds, leaderboard depth, per-league
  display overrides.
- **Settings** — display name, seconds per screen, Screen (idle screens with
  live previews, per-mode pages, timers, quiet hours), Spoilers, Updates,
  Troubleshooting, Advanced.

Every RULE in there is a call into the shared core — ordering, ring
precedence, the picker, descriptor interpretation, the provisioning sequence
and pin grammar. What is Kotlin's own is layout, navigation, permissions,
formatting, and the BLE/Keystore plumbing.

Not built: the firmware developer picker and debug log streaming (both
DEBUG-only on iOS).

## Building

One-time setup:

```bash
# Android Studio (or commandline-tools) with SDK 35 and NDK r27+
rustup target add aarch64-linux-android x86_64-linux-android
cargo install cargo-ndk
export ANDROID_NDK_HOME=~/Library/Android/sdk/ndk/<version>
```

Then:

```bash
./build-core.sh        # libapp_core.so per ABI + fresh Kotlin bindings
./run.sh               # build + install + launch on a device
./run.sh --emu         # ...booting the "scoreboard" AVD first
./run.sh --emu --logs  # ...and following the app's logcat
```

`./gradlew assembleDebug` alone just builds the APK
(`app/build/outputs/apk/debug/app-debug.apk`).

**JDK version matters**: AGP wants 17-21. A newer JDK fails with a bare
version number as the entire error message. `run.sh` defaults `JAVA_HOME` to
the brew `openjdk@21`.

**Testing on your phone**: enable Developer options > USB debugging, plug in,
accept the RSA prompt, then `./run.sh`. The app talks to the hosted server
over TLS, so the phone needs no special network setup.

`build-core.sh` is the only correct way to refresh the core — the same rule
as `ios/build-core.sh`.

## Identity

The Ed25519 controller seed is generated by the core on first launch and kept
in `EncryptedSharedPreferences` (the Keychain sibling). **An Android install
is a new controller**: the server allow-lists controller pubkeys per board,
so this app pairs itself with the code on the panel — it does not inherit an
iPhone's grant.
